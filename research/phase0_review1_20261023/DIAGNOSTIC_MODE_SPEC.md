# データ取得診断モード仕様案

版0.1／未実装。既存コード・Actions変更、ネット取得実行、通知、Sheets書き込みは含めない。

## 目的・入口

対象取引日のSOXX・SOXL・SPY・IEFがそろわない原因を、銘柄別欠損、日付ずれ、取得失敗、計算不備に分ける。2回のDBロックを全欠損原因と決めつけない。

初期状態はオフラインの入力診断。売買・通知・Sheets・認証情報を読み込まない独立処理とする。オンライン取得を行う場合は銘柄・対象日・条件を明示した読み取りモードとし、既存の通知ワークフローを再実行して代用しない。

期待取引日を必須入力とする。自動導出は米国取引カレンダー、通常／短縮セッション、夏冬時間、取得可能時刻を検証してから。単純な前日・平日計算にしない。

## 記録項目

| 区分 | 保存内容 |
|---|---|
| 実行 | コミット、実行ID、取得開始／終了UTC、日本時間、対象セッション、期待取引日 |
| 環境 | Python・yfinance・pandas・numpyの版、指定引数と確認できた有効設定 |
| 構造 | 列名と階層、タイムゾーン、行数、先頭／末尾索引、重複・未整列 |
| 銘柄・項目 | Close/Open有効件数、最終有効日、対象日値の有無・有限性、末尾数行の値またはnull |
| 指標 | 使用日、必要履歴の本数、SMA200／RSI／SHDの履歴充足、共通日、欠損位置 |
| エラー | 銘柄と秘匿化した分類、DBロック等の識別コード。Cookie・秘密URL・生トレースなし |
| 結果 | DATA_VALID／DATA_INVALID／SOURCE_ERROR／DATE_MISMATCH等。売買判定なし |

NaN／InfinityはJSON数値で書かずnullと理由に分け、入力ハッシュと取得時刻を付ける。実口座情報は扱わない。

## 切り分け

1. 4銘柄の末尾と最終有効日を調べ、SOXX・SOXLの欠損とSPY・IEFの共通日欠落を分離する。
2. エラー銘柄の対象日だけか履歴全体が空かを確認。取得エラーと結合後の日付ずれを分ける。
3. 現行版・取得条件を基準にし、並列／直列、保存領域を変える実験は一要因ずつ。使用APIは対象yfinance版のソースで確認する。
4. 直列化や実行別保存領域は候補だが、ロック消失だけで対象日データを正常としない。単回成功で原因確定しない。
5. 再取得回数・間隔・終了条件を限定し、元の失敗も残す。前日値への置換・欠損日削除で正常化しない。

## 受入確認

完全、末尾全欠損、1銘柄欠損、1銘柄履歴全欠損、日付不一致、履歴不足、DBロックの模擬入力を区別する。RSIが数値でも元のClose・履歴が欠ければ有効としない。オフライン確認は通信遮断し、通知・Sheets・口座接続は常に0。元入力と加工を区別し、過去生レスポンスの復元と呼ばない。

実装担当は仕様確定後に選ぶ。メタデータ整形はLunaへ分担できるが、日付・指標の有効性と原因判断は6.1 Sol Highが確認する。
