# SOXL税引後売買戦略 ― ChatGPT Work向け引き継ぎ資料

**作成日：2026年10月23日（日本時間）**  
**目的：** この文書だけで、ChatGPT Workが検証の背景・ユーザーの確定方針・売買ルール・研究データ・暫定結論・未解決の実装問題を理解し、**検証を監査・再現したうえで次工程に進める**ようにする。  
**現在の工程：** 第13回「寄り付き直後、1分後、3分後、5分後の発注タイミング」検証。個別の分足は未収集。第三者の分足／NBBO統計は一部確認済み。  
**重要：** 記載の運用利益は過去の試算値であり、再現検証済みの確定成果ではない。回ごとの実装差・入力データ差に起因する不整合が判明しているため、**Workは最初に計算エンジンと取引台帳を監査すること**。

## 1. ユーザーの目的・確定済み前提

1. **主目的はSOXL売買戦略の最終税引後総資産を最大化すること。** 現金、米ドルMMF、保有中のSOXL時価をすべて合算。期末未売却ポジションがあれば含み損益を必ず算入し、「その日に全売却した場合の推定税引後資産」も別表として併記。
2. **損切りしない。逆指値・ストップロスは導入しない。** 含み損のまま何年も保有する可能性を容認する。最大ドローダウンは把握しても戦略採否の主評価指標にしない。「損切りなし」は含み損や元本毀損の不発生を意味しない。
3. **実現利益は税引後の全額を次の売買に再投資する。** 利益を円転・出金せず、原則USDのまま待機する。
4. **証券会社は楽天証券。** 米国株SOXL現物取引、外貨決済。待機資金は原則として楽天証券で利用できる**米ドルMMF**に置く。MMF直接充当／自動買付サービス利用を検討。手間を減らすことも重要。
5. **為替レートは一律「1米ドル＝150円固定」** とし、日々の為替変動はバックテストに含めない。ユーザーから明示の指示。実際の楽天証券・税務計算とは差が生じるので実約定後の税額照合だけ別途行う。
6. 譲渡益税は現実寄りの比較では**20.315%**を基本とする。初期比較に20%版があり、同一比較では混ぜない。円換算固定150円なら「ドル建て譲渡益 × 20.315%」と代数的に同じ。実際の税金処理は口座区分に依存するため**特定口座（源泉徴収あり）は暫定仮定**であり、ユーザーによる最終確認は未取得。
7. **米国市場終了後に各指標を判定・日本時間早朝にDiscord通知 → 同じ日の日本時間夜の米国通常取引で手動売買。** 自動発注は想定していない。
8. **発注方法は市場開始直後の成行注文を第一希望。** 運用が楽で、寄り付き前の成行注文における108%余力拘束・再拘束リスクを避けたい。直後、開始1分、3分、5分の実証比較を進行中。
9. **Fear & Greed（以下F&G）については目視確認を容認。** システムはその他の技術条件が揃った時に予備通知し、ユーザーがCNNで**その時点の値のみ**確認する。目視では過去数日の微細な変化率、移動平均などは分析しない。ExFearはテクニカル条件不要のため、通常の予備通知だけでは見落とす。別途毎朝の確認通知または自動取得値を参考にした予備通知を設計。
10. **対象期間の解釈：2023年以降（AI・半導体の重要性が高まった時期）を主たる評価対象。** 2024年10月以降のSOXL実始値がある期間、2025年以降の開始日独立比較を重点とする。2011〜2022年の市場環境は参考値に留める。
11. 既存のGitHub `soxl-alert`／Discord通知／Googleスプレッドシート記録は**まだ改変しない**。まず定量検証→正式仕様確定→必要な改修指示の順。

## 2. 現行の売買ルール（未確定箇所は明示）

### 2.1 指標

- **SOXXのRSI(14)**：Wilder式。定義の初期化をテストで固定。
- **SOXXの200営業日SMA**（ほか20日、50日SMAを試行したが主要ルールには未採用）。
- **SHD**：`100 × [SPYの過去20営業日の調整後リターン − IEFの過去20営業日の調整後リターン]` に相当する百分率ポイント差。厳密には `100 × [(SPY_t/SPY_{t-20} - 1) − (IEF_t/IEF_{t-20} - 1)]`。調整後終値の営業日整列必須。
- **CNN F&Gの確認値**。通常買い・ExFear・再エントリーの条件に使う。目視の場合は確認した時刻と値を保存し、後から取得した履歴値で上書きしない。
- **SOXLの取得原価・未実現損益**：売却時の利益判定。複数回購入の平均取得原価を使う。

### 2.2 通常買い（暫定第一候補）

同一判定日の米国市場引け後に、以下がすべて成立：

- `25 ≤ F&G < 30`（**30以下ではなく30未満**）
- `SOXX終値 > SOXXの200日SMA`
- `SOXX RSI14 ≤ 55`
- `SHD < 0`
- 当該条件が前営業日から継続しているだけなら再発火させない（**立ち上がりエッジ**）。
- ExFearの有効な恐怖エピソード中は通常買いシグナルを抑制（過去のモデルの解釈。実運用仕様化時に明文化）。

**購入額：利用可能な税引後USD/MMF資金の100%を上限**（ただし実注文は手数料・気配変動・余力を考慮し、整数株切り捨てと余力バッファを用いる）。すでに保有していれば現金の範囲で買い増し可能。

### 2.3 Extreme Fear買い（ExFear）

- `F&G < 25` で有効な恐怖エピソードの最初の発火を検知。
- 他のテクニカル条件が揃っていなくても買付可能。
- **利用可能資金100%を上限に一括購入（A方式）**が主候補。
- 再発火の準備条件は、`F&G ≥ 30` が**3営業日連続**。この再武装ルールに必要なのは過去3回の確認値であり、ユーザーはF&Gの詳細な変化分析を希望していない。
- 以前、F&G<20・<15で追加投入する「B方式（50/25/25）」も比較したが主候補ではない。
- **実運用課題**：F&GはExFearのみで候補が成立するため、テクニカル条件成立時だけの通知では不足。毎取引日のF&G確認導線が必要。

### 2.4 再エントリー（利確後の再購入）

- 原則、SOXLを**保有していないとき**だけ。
- 直前の全売却から**3取引日以上**のクールダウン。
- `F&G ≥ 30`。
- `SOXX > 200日SMA`。
- SOXX RSI14が **前日55以下 → 当日55超**に上抜け。
- 当日の通常買い／ExFearと競合する場合は、それらのシグナルを優先。発注競合の厳密な処理順は必ず監査する。
- 第一候補：利用可能な**現金の25%**で購入し、残り75%はMMF待機。対照候補：100%再購入。再購入なしもベースライン。
- 以前はRSI55上抜けを20/50日SMAや短期騰落率で追加制限、強トレンド時だけ再投入率を増やす、25%→25%→50%の段階追加も実験。最近の評価期間では**固定25%を一貫して上回る根拠がなかった**。

### 2.5 売却（損切り絶対禁止）

- 当日引け時点で保有SOXLの取得原価に対し**含み益20%以上**、または**SOXX RSI14が75以上**なら翌営業日売却候補。ただし利益が最低2%以上必要なゲートを併用。
- **翌営業日実際の想定約定価格・手数料控除後**に、SOXL保有全体のUSD取得原価に対して**税引前売却益が最低+2%以上**あることを再確認し、満たさなければ売らない。20%利確に達していても寄り付きで下落したら保留。
- **全株一括売却**を主候補。部分売却は探索段階で試行したが未採用。
- 売却時、利益（取得費・売買手数料控除後）に税率20.315%を控除。ドルは円転せず、USD/MMFで次の買い場に備える。
- ※「売却時に2%以上の利益」を確保するのは**モデル上の取引禁止ゲート**であり、成行注文の実約定前に価格を確定できない現実では、約定時に無条件の利益保証はできない。実運用で損失売却を厳禁とするなら価格下限の指値／事前板確認など別設計が必要。ここは**重大な未解決事項**。

### 2.6 信号・発注の時点整合性

- SOXX、SPY、IEFの終値で**取引終了後**に判定し、SOXL注文は原則**翌米国営業日の通常取引開始直後**。
- 日本時間：米夏時間は概ね**22:30**開始、冬時間は**23:30**開始。
- 原則SOXL成行注文。取引可能資金から手数料と必要な価格変動バッファを除き、**整数株**で購入。注文取消／未約定は履歴に残し、モデルは都合よく約定させない。
- F&Gの値は**実際の確認時刻に利用可能だった値**だけを使う。歴史的なCNNの後日更新履歴を市場終了時点で見られた値と同一視しない。

### 4.2 重大な数値不整合（必ずWorkに伝達）

- 第13回の調査中、注文シミュレータの一実装で**再エントリーなし・25%・100%の資産額が完全に一致**し、再エントリー回数がすべて0になる結果が出た。実装時の判定順序（`pendingBuy`処理、`shares===0`判定、条件優先順位等）の不具合または仕様差が疑われる。**その実装の金額は棄却すること。**
- 一方、別の独立チェックで再購入25%の実施日が**2024-10-07、2026-02-09、2026-06-09**（前営業日のシグナルに基づく）と確認できた。新シミュレータの回帰テストに使うこと。
- 第11回と第12回にも開始直後理想約定資産額が `$44,683` と `$44,460` のように異なる。一部は買付余力バッファや注文数量・配当処理の差と考えられるが、差額の完全帰属は**未監査**。前回の数値を正として固定しないこと。
- 利益が20%以上の翌日寄り付きで実際の売値が大幅下落した場合、2%利益ゲートで売らない実装と、成行が既に約定する現実とのギャップがある。**先読み禁止と「損切りしない」の両立方法を仕様として解決**する必要がある。
- **SOXL分配金データに欠落**：過去の実装で明示的に計上したのは2024-12-23、2025-03-25、2025-06-24、2025-09-23の4回だけ。**2025年10月以降〜2026年8月までを完全網羅したわけではない**。分配金込みの損益を「正確な実績」と呼ばないこと。
- MMF収益の計上が「税引前日次→月末再投資」で適切か、実際のMMF残高・自動買付日・約定日・受渡日に沿うか監査が必要。
- SOXL調整後終値と実株価・分配金を混在させると**分配金の二重計上**・税額誤算の原因になる。株数・平均原価・分配は分割後の未調整株価を基準に同一系列で管理。
- 注文を複数出す場合、前日確定時点の資金／当日約定時点の残高を混ぜて使うと、結果に先読みや二重配分が生じる。

## 7. Workが最初に実施すべき工程（優先順位順）

### Phase A — 売買エンジンの再現性監査【最優先】

1. 最新の市場データ取得と重複／欠損／時系列・市場休場日の検査。2024-10-01〜2026-08-10の入力データを**SHA256等で固定**。
2. `signal_date` / `observation_timestamp` / `decision_timestamp` / `order_submitted` / `execution_timestamp` を分け、**同日の将来データにアクセスできない**売買エンジンを実装。
3. F&Gはまず歴史履歴値を**「as-of未検証」**として使用し、結果に注記。`actual_recorded` / `historical_proxy` / `one_day_delay_stress`を明示。
4. シグナル生成器と注文・決済エンジンを分離する。**同じ事前確定シグナル列**に、注文方式だけを差し替えて比較できることを確認。
5. 監査トレース：日付、指標、F&G値、再武装状態、イベントID、全売買候補、売買未実行理由、MMF現金／未払い分配、保有株数、平均原価、手数料、税金、約定価格、総資産。
6. 回帰検証の目安：再エントリー25%版では2024-10-07、2026-02-09、2026-06-09の取引が発生するか照合。**一致しなければ原因特定する**（必ずその日付にするよう無理やり合わせない）。
7. 「損失売却は禁止」「全売却後に平均原価0」「株数非負」「現金非負」「他の買い注文との残高競合なし」「売却注文が失敗した時も保有継続」「未売却分の時価計上」を自動テスト。
8. **事前判定2%利益ゲートと成行約定時の不確実性**を解消。例えば「当日始値で得られる利益を先読みして不成立」にしたモデルは実注文で再現不能。実口座を仮定するなら、実行可能な指値・キャンセル判断基準などで置き換える。

### Phase B — 楽天証券の取引・課税・MMF精緻化

1. 全期間USDJPY150円固定、譲渡益税20.315%、楽天手数料0.495%上限22USD＋SEC Fee、整数株・取得費移動平均の台帳。
2. 税引後の再投資可能現金を正しく計上し、MMFへの移動・そこからの注文余力を楽天の最新ルールに沿ってモデル化。
3. SOXL**全期間の権利落ち日／支払日／一株あたり現金分配／株式分割**を取得し、分配金源泉税・税引後余力・未調整株価と整合。
4. MMF実際の月次税引前実現利回りが取得できれば商品実績に差し替える。なければ年率0/2/3/4%の**仮定別**表示のままにする。
5. 2025-12-21以降の米国株売却代金MMF自動買付は、それ以前に遡って有効と扱わない。利用開始日・対象ファンドは公式確認。

### Phase C — 開始直後の成行 vs 1/3/5分後の比較【今回の焦点】

1. **買い・売りの実行予定日だけ**を抽出（シグナル発生日とは翌取引日の関係）。通常／ExFear／再エントリーの各イベントと区別。約定後に取引経路が変わるため、全候補日と実行日を両方保存。
2. 各実行日について米国東部時間09:30:00、09:31:00、09:33:00、09:35:00前後の**SOXL 1分足OHLC**を収集。可能なら個別約定・気配NBBO・売買気配の深さを取得。
3. 「09:30のオープニングオークション価格」は**09:30:00に成行を送信した注文の約定価格ではない**。時刻別の実行モデルでは、指定時刻後に観測できるbid/askで控えめに評価し、スリッページと実行遅延の幅も出す。
4. **同じ売買シグナルで、成行直後・1分後・3分後・5分後**を比較。買いでは高い価格ほど不利、売りでは低い価格ほど不利。売りの損失禁止・利益ゲートについてもリアルタイム判定可能な仕様にする。
5. 期間は2024-10以降を優先、2025以降の独立開始で再確認。結果は税引後の期末総資産・取引回数・非約定率・スプレッド・最大約定乖離・待機負担などを比較。
6. 真の分足／気配を取得できなければ**秒／分単位の結果を創作しない**。第三者の平均統計を個別シグナル日の最終資産に代入しない。

### Phase D — 通知仕様の明確化（**コード変更は別途承認後**）

1. 米国引け後のテクニカル予備判定、F&G現在値の目視確認時刻、確認者、値、最終条件を記録。
2. ExFearはテクニカル条件なしで起こるため専用の確認導線。
3. Discord通知候補：通常買い（F&G25〜30未満）、ExFear（F&G25未満）、再購入（F&G30以上）、利益確定候補（保有株・平均取得単価・利益・税額・注文方法）。
4. 楽天証券の注文候補株数・手数料・MMF残高・円税額（換算150円）を表示する。ただし最終注文は**手動**。
5. 開始後1〜5分の注文推奨が固まるまで通知の売買文言を確定しない。
