## 2. 取得前にユーザーが確認・選択すること

1. Alpacaに登録して無料のBasic（Paper可）を使うか、そもそも使わないか。使わない場合、時刻別比較は保留のまま。
2. 登録資格（居住地・本人確認の要否）、利用規約（データの保存・再公開・個人利用範囲）を自分で確認。結果は私に連絡不要。キーは送らない。
3. 有料プランへ進まない。Algo Trader Plus等の購読・支払手段の登録をしない。権限不足（403等）で止まったら、それを結果として扱い、IEXへ切り替えない（スクリプトも切替えない）。
4. 実行する場合の保存先を、Git管理外の非公開フォルダに決める（スクリプトはGit配下を拒否）。
5. 実行前に`--plan`で件数・期間を確認する。

## 3. 実行手順（ユーザー本人の環境で）

```
node alpaca_fetch.mjs --plan                     # 既定。通信なし・キー参照なし。計画を表示
# ユーザーが自分のシェルで APCA_API_KEY_ID と APCA_API_SECRET_KEY を設定（値はこのリポジトリ・チャットに出さない）
node alpaca_fetch.mjs --execute --out=/path/to/private/empty/dir [--max-pages=5]
```
Node 22以上、標準機能のみ。対象は固定：日足8日（2024-10-07、2024-12-20、2026-06-30、2026-07-01、2026-07-29、07-30、07-31、2026-08-10）、分足と気配の2日（2024-10-07、2026-07-01）。barsは09:29〜09:37 ET・1Min、quotesは09:29:59〜09:36:30 ET。日付や期間の追加、全履歴取得はしない。

保存物：`raw/`（受信バイトそのまま）、`normalized_*.json`（原値＋時刻ラベルのみ）、`manifest.json`（URL範囲、ページごとのバイト数・SHA256・取得時刻UTC、件数、完了／不完全、欠損、異常）。SHA256は受信バイトに対してのみ付ける。キーは保存しない。

## 4. 扱いの注意

- **足は約定ではない。** 足の始値を成行の実約定価格と呼ばない。09:30に取引がなければ09:30のバーは出ない。欠けた分は0や直後の値で補わない。
- **SIP気配からNBBOの約定可否を断定しない。** quoteの定義が確認できるまでTODO。到着時点より未来のquoteを選ばない。ナノ秒を落とさない。
- **日足は公式終値と違う可能性。** 日足は約定の条件コードで集計され、公式始値・終値の約定は更新に使われない。保存研究（Yahoo、分割調整のみ）と差が出ても、保存研究・順位を上書きしない。差は別定義の可能性として記録する。
- 過去日であっても、endが現在から15分以上前であることを検査する（満たさなければ停止）。
- 生データは非公開フォルダ。公開リポジトリにはコードと、秘密・生値を含まない検証要約だけを置く。
- 時刻別（開始直後／1／3／5分）の比較、執行シミュレーション、数量決定は後工程で、今回作っていない。
