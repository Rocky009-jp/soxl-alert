## 3. 実装する契約

設計書§4〜§9を仕様とする。依頼書は設計の範囲を狭めるためのもので、相反する新しい計算式を追加しない。実装上の矛盾があれば§6の手順を使う。

### 3.1 保存ドメイン

- Snapshot、GENESIS、APPLY、AppendPlanと結果の型を作る。スキーマはS1専用の版1。初期状態以外をGENESISへ取り込まない。
- seq・親hash・event_hash・input_hash・Dの昇順・current_stateを検査し、履歴全体を保存入力から再計算する。
- 現在状態／state_afterの検査はMarketState.from_dict、基点の比較は親state_afterからfixed_decisionとbaseを落とした値に対して行う。正常な基点を現在状態の検査で拒否しない。
- confirmed_inputsは選択decision、D行、前日行またはnull、prev_session_date、必要範囲のsession_context。input_hashには無関係な台帳や市場の後日データを含めない。
- 市場数値の型と範囲、日付、UTC時刻、窓、decision指紋を検査する。スキーマ外・重複JSONキー・非有限数値を拒否する。
- 通常計算はevaluate_day、保存入力からの再計算はapply_transitionを使う。条件式や状態更新式を新規パッケージへ複製しない。

### 3.2 単日ランナー

- 明示Dだけを処理する。snapshot検査、必要セッション確認、台帳照合、コア呼出の順を固定する。
- 台帳は境界以降を含む写し。適用済みdecisionの削除／変更／追加、欠測区間への遅着は停止する。ACKや補完で先へ進めない。
- 初回もGENESIS.start_afterからDまでの未処理decisionを検査する。途中があればintermediate_session_unprocessedとして止める。自動で途中Dを処理しない。
- decision無しは計画なし。新規decisionは1件の準備だけ。同じ最新Dで確定入力・遷移判定・状態が同じなら追記なし。判定が同じでも市場入力が違えばrecompute_mismatch。
- 先に行う台帳照合での削除／内容違いはledger_mismatch。select_decisionが検出する複数decisionやrecord_id競合は既存codeを保つ。コア単体とラッパーの優先順位差を隠さない。
- core_result.state_updatedを保存成功の意味へ変更しない。COMMITTEDはcommit成功時だけ返す。

### 3.3 MemoryStore

- 明示initializeのみ。未初期化を自動で初期状態へ置き換えない。initializeはGENESIS1件のみを受け付ける。
- 同一ロック内の先頭比較・全検査・1回の置換でcommitする。競合側は状態不変のcas_conflict。
- 読取・書込・計画の内側のdictやlistを外から変更できないようにする。
- 成否不明時はreconcileでDと親hash・確定入力・判定・状態を照合する。先頭が進んだだけで成功扱いしない。照合は書かず、競合後に古い計画を付け替えない。
- 同内容で他の実行が保存した場合のALREADY_APPLIEDは、自分の送信権を意味しない。通知のAPIを設けない。

| A-02 初期化・構造 | 未初期化読取、二重初期化、正常GENESIS、APPLYを含む初期化／初期以外のGENESIS拒否、不明版／コアSHA／イベント／項目、seq／親／hash／D重複・逆転／先頭状態の不一致を拒否 |
| A-03 再計算 | 複数APPLYのJSON往復後も全state_afterとtransition_resultが一致。正常な基点を受け付け、基点と親状態の不一致・固定decision指紋不一致を拒否。apply_transitionの実呼出をspyで確認し、返値差替えで不一致を検出 |

| A-05 時系列・台帳 | 境界以前／過去D拒否、初回も含む途中decisionの停止、通常欠測後F&G30以上はstreak=1、初回遅延はgap=falseでもskipped_sessionsあり。適用済みdecisionの削除／変更／別ID追加、同ID内容違い、遅着、必要sessions不足を状態不変で拒否。行順を入れ替えても勝者を選ばない |

| A-07 障害・独立性 | commit直前の検査例外で状態不変、commit成功後に応答を失った想定でも照合により追加0。入力・戻り値・計画の入れ子改変で内部状態が変わらない。JSON重複キー・bool数値・NaN／Infinity・不正日時／窓を拒否。安全な例外に生行やURLを出さない |
| A-08 境界・環境 | 新規コードに通信・実時刻・ファイルパス操作・通知・資格情報の経路が無い。既存evaluate_dayへの委譲を確認し、コアのエラーをNO_SIGNALへ変換しない。対象Python版と全試験件数・失敗／skipを記録。MemoryStoreの試験を耐久保存・複数プロセス・実配信の証明にしない |

A-06の競合は単なる逐次呼出だけで済ませない。Barrier等を用いて同じ先頭から準備した2スレッドを実行し、更新成功数とAPPLY件数を検査する。sleepによる偶然の競合待ちに依存しない。異なるDの計画では、双方を初期同一先頭から作れる台帳条件を明記する。

A-03では保存入力の行を変えてハッシュだけ整えたケースも、状態または判定が変わる入力なら再計算不一致として検出する。すべてのフィールドを書き換え再計算した履歴の真正性まで保証すると主張しない。

A-07の「応答を失った想定」はメモリ内の障害注入である。実ネットワークや電源断を発生させない。エラー発生後も元Snapshotの内容と先頭が一致することを全エラー群で確認する。

前工程で行った43欠陥注入や3114ケース生成を自動的に作り直さない。今回新しい試験の感度確認は、上記の再計算差替え、失敗注入、実際の競合で行う。
