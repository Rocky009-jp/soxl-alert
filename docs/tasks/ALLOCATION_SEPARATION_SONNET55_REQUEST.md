## 2. 固定グリッド（実行前にspecification.jsonへ保存）

| 因子 | 値 |
|---|---|
| 初回トレンド参加率 I | 0%、25%、100% |
| 実売却後再エントリー率 R | 0%、25%、100% |
| 売却あり出口 | P20_OR_R75、P20_ONLY |
| 売却なし出口 | NO_SELL |
| 独立開始 | 2024-10-01、2025-01-02、2025-04-01、2025-07-01、2025-10-01、2026-01-02 |
| 主終端 | 2026-08-10 |
| F&G | delay=0 と delay=1（後者は仮定のストレス） |

売却ありはI×R×2=18候補。売却なしは売却後Rが作用しないのでI別の3候補。合計**21ユニーク候補×6開始×2遅延＝252診断試算**に限定。NO_SELLのR違いを独立した候補として順位表へ水増ししない。回帰／同一性確認の追加実行は別件数として記録する。

初回0%でもR>0の売却後再エントリーは許し、I>0・R=0なら初回参加だけ許す。既存のI=R連動を残したまま分離比較したと報告しない。

## 3. 変更する研究コードと変えない意味

旧 [audit_exit.mjs](../../research/SOXL_exit_study_20261023/audit_exit.mjs) の必要部分を、新規研究フォルダのengine.mjs等へ分離コピーする。旧ソースを編集しない。Node ESM標準ライブラリ中心とし、不要な依存を追加しない。

変えるのは初回と売却後の配分入力の分離だけ。新オプション未指定時は旧比率連動・allowInitialReentryの動作を再現できる形にする。関数の状態意味は根拠コードを確認し、以下を保つ。
- 売却候補＞ExFear/通常＞初回/再エントリー。通常／ExFearは現金100%上限、保有中買い増し可。
- 初回は売却歴なし・未保有でRSI55上抜け等の条件。開始日に無条件で買う処理ではない。実売却後は3取引日以上の待機。
- F&Gのarmed、連続、立上り、欠損時の処理、売り候補とExFearが重なった場合の消費も旧モデルと同じ。この研究だけで実運用へ採用しない。
- 研究の引け時価の20%条件と、費用控除後税引前2%ゲートを分離して維持。RSIはSOXX。2%を新たな正式運用基準としない。
- **執行は旧日足理想始値・事後ゲートの診断モデルを維持。** 翌始値で数量を決める・売却可否を判定する欠点を隠さない。今回、楽天の指値制限や実気配の執行を追加しない。
- 0株／整数株／費用込み平均原価／売却税／現金分配／MMFの会計を保つ。税引後利益全額再投資、初期10,000USD、為替150円固定、税20.315%、手数料・SEC Feeは旧研究と同じ日付別モデル。
- 現金分配は既存dividends_verified.jsonの権利・支払日proxy。MMF3%・日次発生・月次税引後計上・即時余力化は研究仮定。実際の楽天仕様としない。

データは旧研究で使った固定3ファイル（daily.json／daily_adjclose.csv／fear-greed.csv）と分配表を再利用。入力manifestとSHA256を照合する。新価格契約や260行窓へ切り替えず、旧研究の指標入力・初期化・ウォームアップをそのまま使う。入力欠損や疑問を補完・上書きしない。7/30・31同値終値はそれだけで不正と断定せず、原データ未照合の留保を記録する。

## 4. 主評価と終端感度

主評価は2026-08-10の最終**時価総資産**。現金/MMF・保有株時価・税引後未収等を含む。純利益、円150円換算、仮清算後資産を別列へ。

同じ各runの日別記録から、2025-06〜2026-07の各月内の最終保存日時点も抽出する。実日付を表示し、公式カレンダー未照合なら月末proxyと明記する。期待する月末日の欠損を無言で正常扱いしない。開始日より前は対象外。8月は8/10主終端のみで、8/31や9月以後へ延長しない。月末値は日別状態の時価評価で、強制売却を追加しない。

順位は開始日×遅延×終端ごとに比較する。期間長が違う開始日の絶対金額を単純合算せず、月末勝数や多数決を新しい目的関数にしない。終端感度は一般化の留保・次の調査材料。重複期間・月末を独立市場標本や未使用OOS、統計的最適性の証拠としない。最大DDによる減点・制約は入れない。

## 5. 必須の確認

- I=Rの旧互換設定が保存済みの基準・P20_ONLY・NO_SELL等と一致するか、既存summary／ledgerから共有するセルを照合。主開始2つ・delay0の基準は44,682.38522296779／42,339.1533605725、NO_SELL・I25%は47,063.089999255135／45,896.92441879124。差があれば原因が分かるまで順位の結論を止める。
- 全開始・遅延のI=Rセルを旧エンジンと比較し、約定日・株数・手数料・税・原価・最終総資産を照合。浮動小数許容は明示し、金額は1e-6USD程度を基本とする。メタ情報やラベルの差で会計差を隠さない。
- I=0,R>0／I>0,R=0の分離が働くケース、NO_SELLで売却・売却後再購入が0、Rだけ変えてもNO_SELL台帳が同じ、先行口座状態を開始前から持ち越さないことを確認。
- 全252本で現金・株数非負、整数株、0株時原価0、会計恒等式と分配金二重計上なしを確認。事後ゲートで損失売却がないことは診断モデル内の性質であって、実成行の保証ではない。
- 実行環境・コマンド・入力hash・仕様・結果件数を保存。ネットワークを使わず、秘密値も実口座も使わない。
- 必要で意味のある変更テスト・回帰だけを実行。旧通知アプリ95件や設計全体の再試験は不要。
