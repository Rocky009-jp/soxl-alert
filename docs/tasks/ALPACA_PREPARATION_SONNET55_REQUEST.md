## 3. 小さい取得用スクリプト

Node >=22の標準機能だけ等、最小依存で作る。Pythonにする場合も不要な依存追加を避ける。**このタスクでは実行しない実取得機能**として用意する。

- 既定/--planでは通信も秘密値参照も0。URL・日時・feed・範囲・最大件数の計画を出す。
- --execute等の明示指定に加え、ユーザーが自分の環境に設定したAPCA_API_KEY_ID/APCA_API_SECRET_KEYを使う設計。キーをコード/ファイル/URL/出力へ埋め込まない。タスク内で設定・探索しない。
- 読取先はdata.alpaca.marketsの歴史bars/quotesのみ。証券口座・注文API・latest・WebSocketへ接続しない。feed=sipを明示し、権限不足時にiexへ切り替えない。
- HTTPリダイレクトを追わず、タイムアウトと有限のページ上限を置く。非200/429は固定文言とHTTPコードで停止し、無限再送しない。エラー本文・ヘッダー・秘密値をログに出さない。
- 出力先を明示。Git管理フォルダへの生データ保存を拒否する等、誤公開を防ぐ。上書きしない。非公開保存、manifestのSHA256はダウンロードしたバイトに対してのみ付ける。
- 受信バイト/取得日時UTC/要求範囲/レスポンス件数/ページ完了/欠損を記録。未取得を0価格や前日値で埋めない。原応答の値と正規化値を区別。
- 足の左端時刻・America/New_YorkのDSTを明示。仕様に従い、終了境界の含まれ方を検査する。
- 気配のbid/ask/サイズ/単位/タイムスタンプの定義を一次資料か公式SDKから確かめる。定義が取れなければTODOとし、SIP quoteだけでNBBO適合を確定しない。時刻精度を落として前後関係を逆転させない。
- quoteを到着時点より未来から選んだり、足始値を成行の実約定と呼んだりしない。今回は執行シミュレータ/数量決定を作らない。
