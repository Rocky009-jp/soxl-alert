## 実装上の判断（仕様の解釈を含む）

1. **decisionの確定**：補正版の「最初の有効decisionを固定する」と「同じDの複数decisionはCONFLICT」を、次のように実装した。同じDでdecision役割の記録が2件以上あれば（内容が同一の再入力を除き）常にCONFLICTで、順序によって勝者を変えない。適用済みの状態には`fixed_decision`（D、record_id、内容の指紋）を持たせ、同じDの再実行では指紋が一致するときだけ再計算し、違えばCONFLICTにする。
2. **状態に持つもの**：`as_of_d`、armed、確認済み連続数、前日normal_raw、`fixed_decision`、直前の基点`base`（同日再実行の再計算用）。口座・保有に関する値は持たない。`fixed_decision`にはrecord_idが入るため、**record_idにURL等を入れると保存した状態に残る**。出力本文・エラー文には出さない。運用ではrecord_idに秘密を入れない約束が要る。
3. **当日未観測**：状態を更新せず、次のセッションを処理するとき前のセッションが処理済みでなければ欠測として、armedを不明・連続数を0にする（S-2(a)で現行規則の維持が決定済み。ただし、その間のセッションに有効なdecisionが入力にあるのに未処理のときは欠測とせずR-02で拒否する）。これは研究のsignals()（欠測日にarmedを変えない）と意図的に異なり、A1では欠測のない区間と欠測後を分けて検証した。
4. **前日normal_raw**：欠測後でも、前日の市場側条件が不成立なら確認済みfalse、成立していれば不明。初回（状態なし）も同じ。
5. **SPY／IEFの空欄**：研究のJS実装は`Number("")`＝0として計算するが、本コアは欠損（None）として扱い、SHDが使えなければ運用エラーにする。固定fixtureでこの差が出るのは2026-08-11以降の行だけで、保存CSVの範囲（〜2026-08-10）には影響しない。
6. **b\***：SOXL D終値は分配未調整のClose（`close_split_adjusted_not_dividend_adjusted`）だけを受け付け、Adj Closeの代用は拒否する。出力は常にP20の参考として1行出し、SOXL終値が入力にないときは表示しない。実通知への送信は別承認のまま。
7. **decisionの窓**：`close(D) ≤ observed_at < open(next(D))`。supplementalは窓を検査しない（値と時刻の形式は検査する）。
