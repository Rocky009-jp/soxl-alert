# モデル分担ポリシー

## 割当と役割
- **6.1 Sol High**が難易度を判断し、作業を割り当て、統合責任を持つ。Claudeへの依頼モデルも6.1 Sol Highが選ぶ。利用可能なClaudeモデルは **Opus 5.5** と **Sonnet 5.5**。
- **Luna**は、ログの既定形式への整理、リンク・表記・文書の整形、仕様確定後の小範囲作業を担当する。
- **6.1 Sol High**は、故障原因の判断、時系列の先読み、会計、取引・保有状態・損切り禁止、設計・仕様の採否、秘密情報や本番影響の判断を担当する。
- **Claude Sonnet 5.5**は、通常の差分、明確な仕様の実装、診断根拠や再現結果のレビューに使う。
- **Claude Opus 5.5**は、複雑な取引仕様、会計・先読み・損切り禁止、大きな設計や採否判断、またはSonnetで重大な未解決点が残る場合に使う。
- 戦略の採用と本番切替はユーザーが承認する。

## Claudeへの依頼
依頼ごとに、指定モデルと選定理由、対象、期待成果を明記する。常にOpusを使う運用にはしない。モデル名だけから消費削減倍率や性能を保証しない。

## Lunaへの依頼の固定項目
依頼には必ず次を明記する。
1. **入力** — 根拠となるログ、仕様、参照情報。
2. **対象ファイル** — 編集を許可するファイルを列挙。
3. **禁止範囲** — 変更・操作してはならない領域や外部送信の有無。
4. **期待結果** — 形式、内容、完了条件。
5. **確認方法** — 実施する確認と報告内容。

曖昧さ、仕様変更の必要、または計算差異が見つかった場合、Lunaは独断で進めず6.1 Sol Highへ戻す。

## 効果測定
モデル別のトークン節約効果は未計測であり、数値を断言しない。

## 依頼単位の制限と現在地

担当者には対象ファイルと許可範囲を毎回明示する。過去の単独タスクの「この文書だけ」という制限を、以後の別依頼へ自動適用しない。Lunaは今回、貼り付け用プロンプトの定型整理を担当し、6.1 Sol Highが内容を確認した。


現在：Opus 5.5の売買ルールレビューを429f90eで受領し、6.1 Sol Highが主評価・楽天の時間帯・F&G記録の解釈を補正した。次は[Sonnet 5.5の限定比較](tasks/ALLOCATION_SEPARATION_SONNET55_REQUEST.md)。初回／再エントリー配分の分離だけを研究コードへ入れ、21候補×6開始×2遅延の252診断試算へ固定するため。大きな戦略採用や執行方式の新規判断は行わない。LunaはF&G空様式の定型整理、6.1 Sol Highは範囲・照合・解釈を担当。追加の全面的Opusレビューは不要。本番反映・停止解除・起動・実送信は未承認。
