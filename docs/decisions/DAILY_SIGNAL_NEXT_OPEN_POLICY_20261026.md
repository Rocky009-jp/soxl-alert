# 日足判定・次回開場での手動購入を軸にする方針
2026-10-26（日本時間）／6.1 Sol High
資料開始：bd9dc17a5c77f1158c0f9299a9672e772a5c7e3b。

根拠：ユーザーは、米国市場の閉場後の値を元に朝通知し、夜の次回開場に合わせて手動購入する簡素な流れを希望した。「売買のタイミングを日足単位で計測するシステム」を本運用の軸とする。

## 運用の軸

| 段階 | 扱い |
|---|---|
| 条件判定 | 確定した米国セッションDの日足と、その時点で利用できる情報で判定 |
| 朝の通知 | 対象D、次回取引セッション、条件成立/未成立/データ不備、F&G未確認を区別して表示 |
| 夜の購入 | 次回開場に合わせユーザーが手動購入する想定。休場・短縮取引・夏冬をカレンダーで扱う |
| 研究上の価格 | 次回取引日のOpenを代理約定価格とする。実際の約定価格や全量成立の保証ではない |

「翌日」は次の取引セッションを指す。休日に常に翌暦日の夜へ発注予定を置かない。朝の通知は発注ではなく、約定や保有を自動更新しない。

## 今回決まったこと

- 売買ルールの検証を優先。設計案の詳細補完や通知コード実装は、その後に必要な範囲で進める。
- 買付を次回開場で行う方針を日足比較の共通条件にする。買い時の日を選ぶ条件、初回配分、再エントリー率、日足での利確条件を中心に検証。
- 開始直後/1/3/5分の最適化、分足/NBBOの取得は当面スコープ外。未検証のまま記録するが、日足仮定付き比較の開始条件にしない。
- Alpaca等の新規API登録・認証・課金・追加取得は保留。保存済みの日足・F&G履歴・台帳を使う。

## 研究上で区別するもの

Dの終値で合図を決め、次回Openを評価上の代理価格とする時系列は、日足での比較に使える。そのOpenを朝に知っていたとはしない。

ただし既存研究には、次回Openに応じた株数決定と事後2%売却ゲートがある。固定入力での損益試算として保持し、実運用で同じ数量/売却成立を再現できる成績と呼ばない。朝の候補判定、注文条件、仮の約定と会計を分けて示す。旧研究を黙って修正して過去数値を変えない。

損切り禁止は維持する。朝に利益があっても、夜の無条件成行売りで損失を防げるとは限らない。**次回開場での買付方針を、無条件の成行売却の採用と読み替えない。** 売却条件の日足検証は続け、実運用の売却注文方式は別に残す。

F&G履歴はas-of未検証の代理値。実運用はユーザーが目視した現在値を使う。目視確認の時刻や、夜の再確認を行うかは未決。朝の通知だけでF&G込みの購入条件が確定したと表示しない。
