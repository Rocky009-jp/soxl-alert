補足：
- 任意連携を**明示的に無効**にした場合（Sheets無効など）は失敗とせず、サマリに「記録は無効設定」と書く。**必須設定の欠落**はエラーで、無効とは区別する。
- 数値のRSIが残っていても、対象日の元価格が欠損なら有効としない。前日値補完や古い共通有効日への後退を最新日の復旧と呼ばない。

## 3. 失敗時の順序・ログ・限界

1. **順序**：データ検査 → 有効時だけ判定・Sheets価格行記録 → 通知 → 終了コード決定。検査NGでは判定せず、通常の価格行も追記しない。理由はログ等へ残して運用エラーを通知する。Sheets有効構成の書き込み失敗は「記録失敗」を保持して通知まで進み、最後に非0。
2. **通知失敗時**：明示的なHTTPエラーは「通知失敗」と非秘密のHTTPステータス、応答がなく作成結果を判定できない場合は「配信不明」として対象日と記録する。URL・応答本文・生例外は出さず、いずれも非0。正常完了として表示しない。
3. **再試行**：配信不明時は自動再送しない案とする。明示的失敗での再試行は上限・対象エラーを別に定義し、未定のまま自動再試行を追加しない。再帰・無限再送を入れず、通知の再送が候補の再生成や保有状態更新を起こさない。
4. **重複防止の範囲**：結果通知と売買候補通知の重複防止は別管理とする。手動再実行の扱いは実装時に確認事項とする。
5. **限界（明記事項）**：
   - 同一ワークフロー内の完了処理では、ワークフロー自体の未起動、実行基盤全体の停止、同一Webhookの故障を検知・通知できない。
   - 対応は「確認期限（JST）までに完了通知が届かなければ未確認」という運用規則（§7-1・§8）。自動検知には独立監視が必要で、採否・権限・費用は別判断。新規サービス導入は既定案にしない。
   - GitHub Actionsの失敗通知は、ユーザーが受信者・設定・到達を確認するまで**未設定扱い**。
   - 通知APIの受付成功は、ユーザーの読了や実配信を意味しない。

## 4. 保有スナップショット（暫定・第一候補）

**暫定版の範囲**：本節は項目定義・責任・鮮度の論点を残す資料であり、**Sheets拡張・読取・原価計算の実装は後工程（正式V2の工程2以降）**。暫定版は保有情報を取得しない。取得しないことは、保有や原価の検査が通ったことを意味しない。
- 未知の保有を0株と仮定しない。
- 保有状態に依存する出力（非保有判定、初回参加／再エントリー分類、追加買い可否、推奨数量・配分）は暫定出力に入れない。入れる場合は必要入力（本節の項目）を復活させる論点として戻す。

将来方式（案）：**ユーザーが確認した手動スナップショットを非公開の保存先から読む**。第一候補は既存の非公開Google Sheetsの拡張（タブ追加・権限変更・読取は今回行わない）。公開GitHubファイル／平文コミットは保管先にしない。証券口座APIは追加しない。実口座の数値はGitHubへ記録しない。

| 項目（案） | 定義 |
|---|---|
| 保有確認状態 | `確認済み保有` / `確認済み0株` / `未確認` の3値。未入力＝未確認（0株ではない） |
| 株数 | 整数。確認済み保有のときのみ必須 |
| 総取得原価（USD） | 保有分の**購入費用込み総額**。時価・円換算表示値と混ぜない |
| 平均原価 | 株数>0のときだけ 総額÷株数 で導出。入力しない |
| 参照元 | 何を見て入力したか（例：約定履歴の画面）。口座番号等は書かない |
| 最終変更時刻 | 実際の約定・入出庫等の最終変更時刻 |
| ユーザー確認時刻 | ユーザーが確認した時刻。**アプリの読込時刻で代用しない** |
| 確認対象セッション | どの取引セッションを確認したか |
| 未反映イベント有無 | 未約定・部分約定・未反映の有無。不明＝状態未確認 |

責任と鮮度：
- 入力・確認・約定後更新の責任はユーザー。アプリは整合性（株数と原価の組、対象セッション、時刻の前後関係）を検査するだけ。通知では値を更新しない。
- 未入力≠0株。明示的な0株と不明を分ける。
- 最終変更がない長期保有を日数経過だけで損切り扱いにしない。外部取引がなかったことも推測しない。
- 売却可否を扱う場面では「対象セッションに対するユーザー確認」と「確認後の未反映イベントの扱い」が必須。**確認頻度・有効期限は未決**（§8に選択材料）。
- **重要**：将来、保有入力が整っても、執行価格・費用・注文不成立等が未確定の本暫定版では、「原価が有効なら売却を推奨できる」と結論づけない。

## 5. 参考情報と売却推奨の境界

- 本暫定版は、保有・原価・費用・執行条件を確認する仕組みが整うまで、**売却推奨・全額売却・緊急脱出の案内を出さない**（R-02暫定案）。
- **暫定版の推奨は、R-02の過熱条件（旧条件）による参考通知を出さない（OFF）**。旧条件は旧売却通知と同じ発火条件のため、名称や注意文だけでは誤解防止に十分でない（6.1 Sol High判断）。
- OFFは完了通知・運用エラー通知をOFFにする意味ではない。正式な利確基準の変更・採用でもない。
- 参考通知ONは、ユーザーが明示的に選んだ場合の**未採用の別案**。既定動作・承認済み機能・実装前提にしない。必要になった時に文言と条件を改めて確認する。
- 以下はON案の記載で、**未採用案の確認項目**：旧条件 `RSI >= 70 OR SHD >= 3.0` を**技術参考情報専用の暫定条件**として分離。既存挙動との対応を追うためで、将来利益の優位性や正式採用を意味しない。
  - 表示は「技術参考情報」。行動を促す「売却推奨」「全額売却」等を使わず、否定・未判定の説明として「売却可否は未判定（保有・原価・執行条件未確認）」を併記。単語「売却」自体を禁止する規則ではない。
  - データ有効性と対象日一致の検査を必須とし、古いSHDでは発火させない。
  - 研究候補（RSI75・利益20%・2%ゲート）は未承認のため混ぜない。閾値探索・新規利確ルールは範囲外。
- 参考情報の通知は約定・売却済みとして記録しない。
