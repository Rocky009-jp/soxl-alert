## 1. 結論と成立条件

1. **P20合図**は「実保有株数n×D終値÷費用込み原価B−1≥20%」。確認済みのn>0かつB>0（有限）のときだけ、1株原価b＝B/nを使って「b≤D終値÷1.2」と書ける。翌Openでの実現利益20%や、研究の2%ゲートの成立を意味しない。
2. **損失を出さない数値の下限価格は、現時点では示せない。** 次の事実（§6のF1〜F4）が公式資料か実口座の記録で確認できるまで、数値の下限価格と実注文の候補（S3）を保留する。
   - 手数料の計算単位と丸め。
   - 部分約定への費用の帰属。
   - E1・E2以外の費用がないこと。
   - 指値の執行の扱い。
3. **費用の上界について（PM-01）**：E1・E2の料率と上限だけからは、任意の一部約定に帰属する費用C_kの上界は導けない。§3(b)の式は、追加の仮定M1〜M4を置いた数学上の条件付き参考例であり、実務で「どの分け方でも成り立つ」とは言えない。
4. **楽天の指値の受付範囲**
   - 売り指値は、基準価格から一定幅（50USD超は3%、25超〜50USD以下は5%、25USD以下は10%）より下には置けない。
   - 基準価格は、楽天の受付制限上の区分で決まる（§2のE6、§3の注記）。
   - 画面の表示価格が、実際の注文の基準と同じである保証はない（楽天の記載）。
5. **日足では指値の約定・不成立・約定の順序が分からない。** 不成立なら保有を続ける。研究の「翌Openで事後2%ゲート」とは別の経路になる。
   - 既存のP20_ONLY I25/R25の主2開始の経路では、8回の売却のうち3回（2026-01-07、07-01、08-05）で、翌OpenがD終値の97%を下回っていた。両開始で同じ日付で、独立した3事例ではない。
   - 出典は5f2593eのevent_comparison.csvの既存の値。
   - これは日足価格の上での記述で、実際の注文の受付・失効・約定を観測したものではない。研究の損益を手動指値運用の見込みとして使えない。
6. **gは未採用。** g=0は損益分岐の数学的な例で、新しい戦略の採用ではない。研究の2%を実運用の下限へ移さない。
7. 無条件の成行売り、逆指値による損切り、終端での損失確定の強制売却は追加しない。買付は朝の確定日足判定→次回開場での手動購入のまま。

## 3. 数式と適用範囲

記号：n＝確認済みの実保有株数（n>0）、B＝費用込み原価（USD、B>0）、b＝B/n、g＝未採用の追加利益率（g≥0）、ρ＝0.00495＋0.0000206＝0.0049706（E1・E2、確認日時点）。

損益は次の3つを区別する。
1. **全量合計の経済的損益**：全ての約定の代金合計−費用合計−B×(1+g)。
2. **各約定部分の経済的損益**：k×q_k − C_k − B_k×(1+g)。C_kとB_kの帰属の仕方に依存する。
3. **税務上・画面上の損益**：楽天や税務の取得価額・円換算に依存する。本書では確認していない。

1が非負でも、2が全部分で非負とは限らない。主担当の論理例：100株・b＝40、全て40.23で約定し、集約費用20.01を最初の1株へ帰属させると、全量は4002.99で原価4000を上回る。しかし、その1株は20.22で原価40を下回る。楽天の実務の観測ではなく、配分が未指定であることを示す例。

**(a) 全量を1回で約定するモデル（既存§5）**：`n×p − C(n,p,d) ≥ B×(1+g)`。C(n,p,d)は、E3（計算単位・端数）が確認できるまで正確に計算できない。参考の式にとどめる。

**(b) 数学上の条件付き参考例（実務未確認・実注文に使わない）**

次の仮定を全て置いた場合に限る。
- M1：手数料とSEC Feeは、各約定（k株・価格q）ごとにE1・E2の料率で別々に計算する。費用の項目はこの2つだけで、各項目の丸めはセントへの切上げ以下。
- M2：各約定の費用は、その約定だけに帰属する。集約された費用を他の約定や一部の株へ配分しない。
- M3：売却時の現地費用は、E1・E2以外にない（USD決済）。
- M4：原価の割当はB_k＝b×k（平均原価、モデル上の定義）。楽天や税務の取得価額と同じとは決めつけない。

この下では`C_k ≤ ρ×k×q + 0.02`となる。そのため次の条件で、2（各約定部分）の非負が数学上成り立つ。

`q ≥ L_ref ＝ ceil_cent((b×(1+g)+0.02)/(1−ρ))`

（I2の推論で、q≥Lを満たすためにL≥L_refとする。）

- 数値例（仮定値で実口座ではない）：b＝40.00、g＝0なら、40.02/0.9950294＝40.2199171200…で、L_ref＝**40.22**（PM-04で訂正。原稿の40.23は1セント高く、最小の切上げではない）。
- この例は実際の下限としての採用を意味しない。
- M1〜M4はどれも未確認（E3・E9・E10）。0.02を別の定数へ増やしても、保証にはならない。

**適用範囲の外**

- 円建ての税務（為替差損益、取得価額の円換算）。研究の150円固定・20.315%は変えない。
- 企業行動（分割など）でn・Bが変わった場合。
- 約定の取消・訂正で数量が変わった場合。

**受付範囲との関係**：置ける指値は、楽天の受付下限＝ceil_cent(基準価格×(1−幅))以上（E6）。数値の下限価格が保留の間は、受付範囲の情報だけを示す。損失回避の根拠にはしない。

## 4. 手動注文・通知の状態表

**鮮度の条件（案）**：確認日時以降に、未記録の注文・約定・訂正・分配・企業行動がないこと。売買がなければ株数と原価は変わらないので、確認が古いだけで無効にはしない。ただし、未約定の注文があった夜の後は、その夜の取引終了後の確認が必要。

- 利用者が選ぶのは、g・モデル上の原価配分・入力方法など。
- F1〜F4のどれかが未確認・変更検知・確認の失効のいずれかなら、S3を出さない。「崩れたと分かるまで有効」というデフォルトは置かない。

**0株と全売却の区別（PM-03）**
- 0株の事実だけでは、全売却の確認にも、再エントリー待機の起点にもしない。
- 新規の0株や口座移管を、全売却歴へ変換しない。
- 全売却は、約定報告に対応する1件のイベント（約定セッションの日付と約定の識別）として記録する。訂正は同じイベントを更新し、新しいイベントを足さない。同じDを再実行しても二重に加算しない。

**送信の境界（PM-05）**
- S0〜S1で示すD終値・b*＝D終値÷1.2・式の常時提示も、未採用の戦略の参考出力である。
- S2〜S5だけを止めれば既存承認#4を満たす、とは扱わない。本書の全ての出力は採用前で、実送信はしない。
