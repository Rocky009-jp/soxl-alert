## 4. 特に見てほしいとされた点

### 4.1 Yahoo・NYSEに環境から届かず、応答の形をS4-Eの試運転で確かめるとした点

妥当。理由：

- S4-Dは取得の関数を外から受け、解釈だけをする。形が想定と違えば、どの違いも`input_market_response_invalid`・`input_market_history_short`・`input_market_value_invalid`のどれかで止まり、その対象Dの判定なしが1通届く（試行S3・S10、Z2）。黙ることも、違う値で判定することもない。
- 想定した形（`chart.result[0]`の`meta.symbol`・`timestamp`・`indicators.quote[0].close`・`indicators.adjclose[0].adjclose`、誤りのときは`result`がnullで`error`に中身）は、公開されているchart API v8の形として広く知られているものと合っている。ただし、このレビューも取得先に届かなかったので、実物では確かめていない（推測でなく、未確認とする）。
- 足りないのは、試運転で何を見たら本番に進むかの基準である。P-03に挙げた。今の通知ツールのActionsで最新の価格の欠けが起きている事実があるので、失敗の率と代わりの取得先の判断は、試運転の前に決めておくのがよい。
- N-01は、取得先の挙動（取引時間中の日足）に関わる指摘だが、試運転を待たずに設計で直せる。
