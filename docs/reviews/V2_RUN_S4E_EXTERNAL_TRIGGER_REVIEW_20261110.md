### 3.1 重大が無い理由・D-1〜D-5 への意見

- D-1（cron-job.org）：無料・最短 1 分・失敗のメール・25 回を超える失敗で無効化（FAQ で確認）。秘密が平文でジョブの設定に残る点は B・C より弱いが、トークンの範囲が小さいので受け入れられる。推奨どおりでよい（P-01 の切替えの条件を足す）。
- D-2（トークン）：推奨どおり。権限は Docs で必要十分。期限 1 年でよい（GitHub は期限の前にメールで知らせる。cron-job.org の 401 の失敗のメールが 2 つ目の知らせ）。
- D-3（`schedule` を予備に残す）：推奨どおり残す。月 88 分前後で、共有の枠の約 5%。外部の 2 回が取得の失敗で終わった朝も、遅れた予備の run が取り戻す（昼ごろ、夜の寄付きの前）。枠が苦しくなったら外せばよい（外すのは workflow の 2 行の削除で、すぐ戻せる）。
- D-4・D-5：推奨どおり。

採用しても、送信・コード・本番の境界は変わらず、誤った判定や重複の通知を生む経路は見つからなかった。N-01 は試運転の記録だけに関わる手順の抜けで、1 行で直る。
